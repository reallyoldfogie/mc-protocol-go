# Ground Truth Validation

This tool validates the Go packet parser against ground truth test cases generated by [node-minecraft-protocol](https://github.com/PrismarineJS/node-minecraft-protocol), a widely-used JavaScript reference implementation.

## Purpose

The existing packet validation (`cmd/packet-validation`) performs round-trip testing (parse → serialize → compare bytes), which validates serialization correctness but doesn't verify that parsed **field values** are correct.

Ground truth validation solves this by:
1. Using node-minecraft-protocol to serialize packets with **known field values**
2. Parsing those bytes with our Go implementation
3. **Comparing the parsed values** against the known ground truth

This cross-validation against a different implementation helps catch parsing bugs that round-trip testing might miss.

## Installation

The test packet generator requires Node.js:

```bash
cd testing/packet-generator
npm install
```

## Usage

### 1. Generate Test Packets

First, generate test packets with known values using the packet generator:

```bash
cd testing/packet-generator
node generator.js --output test-packets.jsonl
```

This creates a JSONL file where each line contains:
- `groundTruth`: The known field values
- `serialized`: Hex-encoded packet bytes from node-minecraft-protocol
- `packetName`, `description`, etc.

### 2. Run Validation

Validate the Go parser against these ground truth packets:

```bash
# From project root
go run ./cmd/groundtruth-validation -test-file testing/packet-generator/test-packets.jsonl

# Show successful validations too
go run ./cmd/groundtruth-validation -test-file test-packets.jsonl --show-success

# Fail the process if any validations fail (useful for CI)
go run ./cmd/groundtruth-validation -test-file test-packets.jsonl -fail-on-errors

# Write machine-readable JSON and render reports in one go
go run ./cmd/groundtruth-validation -test-file test-packets.jsonl \
  -json tmp/groundtruth-results.json -html tmp/report.html -md tmp/report.md

### Multiple Files, Globs, and Directories

You can validate across many JSONL files:

```bash
# Glob expansion (shell expands *)
go run ./cmd/groundtruth-validation -test-file "testing/generatedPackets/*.jsonl" -html validation.html

# App-side glob and directories via -test-paths
go run ./cmd/groundtruth-validation -test-paths testing/generatedPackets,/another/dir/*.jsonl -md validation.md

# Combine with version filtering
go run ./cmd/groundtruth-validation -test-paths testing/generatedPackets -version 1.21.5 -json gt-1.21.5.json
```

If both `-test-file` and `-test-paths` are set, files from both are merged (de-duplicated).
```

## Understanding Type Differences

Some "failures" are expected differences between JavaScript and Go type systems:

### Bitfields
**JavaScript**: Plain number `0`
**Go**: Typed struct `PositionUpdateRelatives({0})`
**Status**: ✅ Expected difference - our bitfield implementation is correct

### BigInt
**JavaScript**: String `"12345678"` (JSON doesn't support BigInt)
**Go**: `int64(12345678)`
**Status**: ✅ Expected difference - values match

### NBT/JSON
**JavaScript**: JSON string `{\"text\":\"Hello\"}`
**Go**: `models.NBTField` struct
**Status**: ⚠️  May need field-level parsing to compare content

### Field Name Differences
Some fields may have different names or not exist in one implementation.
**Status**: ⚠️  Indicates protocol implementation differences

## Adding Test Cases

Edit `testing/packet-generator/generator.js`:

```javascript
testPackets.push(generateTestPacket('packet_name', {
  field1: value1,
  field2: value2,
  // ... all packet fields
}, 'Description of what this tests'))
```

Then regenerate:

```bash
cd testing/packet-generator
node generator.js
```

## Supported Packets

Currently supports simple Play state packets. Complex packets (player_info, chunks, commands) may need special handling in the generator.

## Limitations

1. **Type System Differences**: JavaScript and Go have different type representations
2. **Play State Only**: Currently assumes all packets are in PLAY state
3. **Protocol Coverage**: Only tests packets that node-minecraft-protocol supports for 1.21.5
4. **Deep Comparison**: Complex nested structures may need custom comparison logic

## JSON Output and Reports

The validator can emit machine-readable JSON, which can be rendered into HTML or Markdown reports.

### Emit JSON (and optional reports)

```bash
go run ./cmd/groundtruth-validation -test-file testing/packet-generator/test-packets.jsonl \
  -json groundtruth-results.json -html report.html -md report.md
```

JSON shape:

```json
{
  "versions": [
    {
      "version": "1.21.5",
      "results": [
        { "description": "...", "packetName": "ClientboundX", "packetID": 42, "success": true, "errors": [] }
      ],
      "summary": { "total": 5, "success": 3, "failed": 2 }
    }
  ],
  "total": { "versions": 1, "tests": 5, "success": 3, "failed": 2 }
}
```

The report shows a table per version with packet name, ID, status, and errors/notes.

## Exit Codes

- 0: Program executed successfully. This includes cases where validations failed (non-fatal) — unless `-fail-on-errors` is set.
- 1: Fatal error running the tool (e.g., bad flags, unreadable test file, report write failure). Also returned if `-fail-on-errors` is set and any validations failed.
